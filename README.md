# rs-water — помпа для води 💧

Легкий, швидкий, **mobile-first** інтернет-магазин помп для води з кошиком та повноцінною **адмін-панеллю**. Побудований так, щоб миттєво деплоїтись на **Firebase Hosting** і легко передаватись клієнту під ребрендинг/перепродаж.

> Storefront + кошик + admin panel, готові до деплою. Дані зберігаються локально в браузері — жодного бекенду для старту не потрібно.
>
> ℹ️ Бренд — **rs-water** (світла синьо-блакитна тема). Наразі сайт деплоїться у Firebase-проєкт `smart-dim`; після створення проєкту `rs-water` достатньо змінити `projectId` у workflow та `.firebaserc`.

---

## ✨ Можливості

**Вітрина (`/`)**
- Адаптивний, mobile-first дизайн у світлій синьо-блакитній темі, з плавними 60fps анімаціями (Framer Motion).
- Динамічний слайдер зображень товару (свайп/перетягування, крапки-індикатори).
- Картки товарів, перемикання категорій, модальні вікна, мікро-взаємодії.
- **Кошик**: додавання товарів, зміна кількості, підсумок і оформлення замовлення через месенджери.
- Плаваюча кнопка **«Купити»** та швидкий зв’язок (Телефон, Telegram, WhatsApp, Viber).
- Блок **«Наші переваги»** та футер з описом компанії й контактами.

**Адмін-панель (`/admin`)**
- Вхід за логіном/паролем (за замовчуванням `admin` / `admin`).
- Зміна логіна та пароля.
- Повний **CRUD** товарів: назви, галерея зображень, опис, характеристики, ціни, знижки, «рекомендовані».
- Завантаження фото з пристрою (з автоматичним стисненням) або за посиланням.
- Редагування **усіх текстів** сайту: банер, переваги, футер, назва, валюта.
- Редагування **контактів** (Телефон, Telegram, WhatsApp, Viber).
- Резервне копіювання: **експорт/імпорт** усіх даних у JSON, скидання до демо-даних.
- Демо-каталог із зображеннями-заглушками одразу «з коробки».

## 🧱 Технологічний стек

| Шар | Технологія | Чому |
| --- | --- | --- |
| Збірка | **Vite 5** | Миттєвий dev-сервер, оптимізований прод-бандл |
| UI | **React 18 + TypeScript** | Надійність та типобезпека |
| Стилі | **Tailwind CSS 3** | Легкий, консистентний дизайн |
| Анімації | **Framer Motion** | Плавні 60fps переходи та жести |

Продакшн-бандл: **~116 КБ gzip** сумарно (з анімаціями та роутером).

## 🚀 Швидкий старт (локально)

Потрібен **Node.js 18+**.

```bash
# 1. Встановити залежності
npm install

# 2. Запустити дев-сервер (http://localhost:5173)
npm run dev

# 3. Зібрати продакшн-версію у папку dist/
npm run build

# 4. Локальний перегляд зібраної версії
npm run preview
```

Адмін-панель: відкрийте `http://localhost:5173/admin` → логін `admin`, пароль `admin`.

> **Важливо:** одразу після першого входу змініть логін і пароль у розділі **Налаштування**.

## 🔥 Деплой на Firebase Hosting

### 1. Один раз: встановити Firebase CLI та увійти

```bash
npm install -g firebase-tools
firebase login
```

### 2. Створити проєкт Firebase

1. Відкрийте [Firebase Console](https://console.firebase.google.com/) → **Add project**.
2. Придумайте ID проєкту (наприклад, `smartdim`). Це визначає домен `https://<project-id>.web.app`.
3. У консолі: **Build → Hosting → Get started** (Firebase Hosting активується автоматично при першому деплої).

### 3. Прив’язати цей код до вашого проєкту

Файл [`.firebaserc`](./.firebaserc) вже налаштований на проєкт **`smart-dim`**:

```json
{
  "projects": {
    "default": "smart-dim"
  }
}
```

> Якщо ваш реальний Project ID інший (Firebase іноді додає суфікс, напр. `smart-dim-a1b2c`) — замініть значення `default` на точний ID з **Firebase Console → ⚙️ Project settings → Project ID**. Або виконайте `firebase use --add` і виберіть проєкт зі списку — CLI сам оновить `.firebaserc`.

### 4. Зібрати та задеплоїти

```bash
npm run deploy
```

Ця команда виконує `npm run build` і потім `firebase deploy --only hosting`.
Можна і вручну:

```bash
npm run build
firebase deploy --only hosting
```

Після деплою сайт буде доступний за адресою:

```
https://<project-id>.web.app
```

Для нашого проєкту — `https://smart-dim.web.app`.

Конфігурація хостингу вже налаштована в [`firebase.json`](./firebase.json):
- `public: "dist"` — деплоїться зібрана папка.
- SPA-rewrites — усі маршрути (включно з `/admin`) віддають `index.html`.
- Кешування статики на рік, `index.html` — без кешу.

## 🤖 Автоматичний деплой через GitHub Actions

У репозиторії є готовий workflow [`.github/workflows/firebase-deploy.yml`](./.github/workflows/firebase-deploy.yml): при кожному пуші в гілку `main` сайт **автоматично** збирається і публікується на Firebase Hosting — вручну деплоїти не треба.

**Одноразове налаштування (лише кліки у браузері):**

1. **Ключ сервісного акаунта Firebase:** [Firebase Console](https://console.firebase.google.com/) → ваш проєкт → ⚙️ **Project settings → Service accounts → Generate new private key** → завантажиться файл `.json`.
2. **Додати ключ у GitHub:** репозиторій на GitHub → **Settings → Secrets and variables → Actions → New repository secret**:
   - **Name:** `FIREBASE_SERVICE_ACCOUNT`
   - **Secret:** відкрийте завантажений `.json` у будь-якому текстовому редакторі, скопіюйте **весь** вміст і вставте сюди.
3. Готово. Тепер будь-яка зміна в `main` (навіть редагування через сайт GitHub) автоматично оновлює `https://smart-dim.web.app`. Прогрес видно у вкладці **Actions**.

> Якщо ваш Project ID відрізняється від `smart-dim`, змініть значення `projectId:` у файлі workflow.

## 🔁 Передача клієнту / перепродаж (re-branding & re-bind)

Цей репозиторій зроблено як **готовий шаблон під перепродаж**. Щоб віддати сайт новому власнику під його бренд і домен:

### Крок 1. Ребрендинг контенту (без коду)
Усе редагується **прямо в адмін-панелі** (`/admin` → відповідні вкладки):
- Назва сайту, тексти банера, переваги, футер — вкладка **Тексти**.
- Контакти (телефон, месенджери) — вкладка **Контакти**.
- Товари, ціни, фото — вкладка **Товари**.
- Логін і пароль адміністратора — вкладка **Налаштування**.

> За потреби фірмовий колір змінюється в [`tailwind.config.js`](./tailwind.config.js) (палітра `brand`) та фавікон у [`public/favicon.svg`](./public/favicon.svg).

### Крок 2. Прив’язати до НОВОГО проєкту Firebase клієнта
Щоб хостинг був на акаунті клієнта:

```bash
# 1. Увійти в акаунт клієнта (або попросити його виконати firebase login)
firebase login

# 2. Підключити його проєкт як default (оновить .firebaserc)
firebase use --add
#   → оберіть проєкт клієнта зі списку та задайте alias "default"

# 3. Зібрати й задеплоїти на його домен *.web.app
npm run deploy
```

Сайт клієнта буде доступний за `https://<його-project-id>.web.app` — **окремо від вашого**.

### Крок 3. Підключити власний домен (custom domain)
У [Firebase Console](https://console.firebase.google.com/) проєкту клієнта:

1. **Hosting → Add custom domain**.
2. Введіть домен (наприклад, `smartdim.com.ua`).
3. Firebase покаже **DNS-записи** (`A` та/або `TXT`), які треба додати у реєстратора домену клієнта.
4. Дочекайтесь верифікації — Firebase **автоматично випустить безкоштовний SSL-сертифікат**.
5. Готово: сайт відкривається за власним доменом клієнта з HTTPS.

> Домен `*.web.app` продовжує працювати паралельно з кастомним — його можна лишити як резервний.

## 💾 Де зберігаються дані

За замовчуванням усі товари, тексти та контакти зберігаються в **localStorage браузера** адміністратора — це робить старт миттєвим і безкоштовним (ідеально для каталогу-вітрини з замовленням через месенджери).

**Наслідки, які варто розуміти:**
- Зміни в адмінці бачить кожен відвідувач цього ж браузера/пристрою; щоб перенести каталог на інший пристрій — скористайтесь **Експорт/Імпорт** у Налаштуваннях.
- Автентифікація адміна — клієнтська (обфускований хеш пароля). Цього достатньо, щоб приховати панель від випадкових очей, але це **не** серверний захист.

### Хочете «хмарний» каталог для всіх пристроїв? → Firestore
Архітектура вже ізольована в одному модулі — [`src/store/store.tsx`](./src/store/store.tsx). Щоб перейти на спільні дані:

1. У Firebase Console увімкніть **Firestore Database** та **Authentication** (Email/Password).
2. `npm install firebase`.
3. Замініть функції `loadData`/`persist` у `store.tsx` на читання/запис у Firestore-колекції.
4. Перенесіть перевірку пароля на **Firebase Authentication**, а доступ до запису обмежте **Security Rules**.

Решта застосунку (компоненти, вітрина, форми) працюватиме без змін.

## 📁 Структура проєкту

```
smartdim/
├── firebase.json          # Конфіг Firebase Hosting (public: dist, SPA-rewrites, кеш)
├── .firebaserc            # Прив’язка до Firebase-проєкту (замініть project id)
├── index.html
├── src/
│   ├── main.tsx           # Точка входу (Router + StoreProvider)
│   ├── App.tsx            # Маршрути / та /admin
│   ├── types.ts           # Типи даних (Product, SiteContent, ...)
│   ├── store/store.tsx    # Стан + збереження (localStorage) + auth  ← точка міграції на Firestore
│   ├── data/seed.ts       # Демо-каталог і початкові тексти
│   ├── lib/               # auth, format, стиснення зображень, заглушки
│   ├── components/        # Вітрина: Header, картки, слайдери, модалки, футер
│   ├── admin/             # Адмінка: логін, CRUD товарів, редактори текстів/контактів
│   └── pages/             # Home.tsx, Admin.tsx
└── tailwind.config.js     # Палітра бренду та дизайн-токени
```
